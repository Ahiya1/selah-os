# SelahOS — Vision (Revision: Ground Phase)

**Created:** 2026-04-01
**Plan:** plan-3
**Revises:** plan-1, plan-2 (SelahOS core + Ground Integrity)
**Mode:** PRODUCTION

---

## Core Principle

SelahOS is not a system for optimization, reflection, or storage.

SelahOS is a **minimal interface for contact with reality**.

It exists to support the user during periods of stabilization, where:
- capacity is limited
- consistency is being rebuilt
- ground comes before meaning

The system must always match the **lowest-capacity version of the user**, not the ideal one.

---

## Purpose

SelahOS enables a simple, repeatable act:

> "Touch reality, without judgment, once per day."

It replaces:
- avoidance → with contact
- narrative → with signal
- self-judgment → with marking

---

## Structural Changes (This Revision)

### Removed Tabs

The following tabs are **removed entirely** from the active system:

- `Project`
- `Signals`

Reason:
- They require reflection, identity, and continuity
- They exceed current system capacity
- They introduce friction and avoidance

SelahOS is not a system for אגירה (accumulation), therefore:
- these tabs are not archived
- they are removed from the current phase

---

### Modified Tabs

#### `Ground` Tab → Restricted Access

- The Ground (weekly stats) view remains **conceptually important**
- It is **removed from daily navigation**
- It is accessed **once per week only**, at a fixed time

Constraints:
- No open access
- No mid-week checking
- No integration into daily flow

Purpose:
- Replace narrative with signal
- Provide bounded observation, not continuous evaluation

---

### Active Tabs (Current System)

SelahOS is reduced to:

- `Today` (only daily interface)

All other surfaces are removed or restricted.

---

## Daily Interface (Today Tab)

Each item supports 3 states:
- ✓ Done
- — Not done (explicit)
- ○ Untouched (default, no pressure)

Tracked domains:
- Sleep
- Food
- Medication
- Body (hygiene / movement)
- Ground (work: maintenance / build)

Additionally:
- Optional **1-line note**
  - No analysis
  - No explanation
  - No requirement

---

## Daily Behavior Contract

- The user is not required to complete the board
- Partial interaction is valid
- Marking "not done" is valid participation
- Leaving items untouched is allowed
- The system records reality — it does not demand improvement

Success condition:

> "Did the user touch the system today?"

---

## Weekly Behavior (Ground View)

Once per week:
- open Ground (stats)
- observe patterns

Allowed questions:
- what is actually happening?
- where is stability present?
- where is it not yet?

Not allowed:
- judgment
- self-criticism
- fixing behavior during observation

The weekly view is:
- bounded
- intentional
- non-continuous

---

## Design Constraints

1. **Low Activation Energy**
   - Must be usable in <2 minutes
   - No typing required for core flow

2. **Non-Judgmental Structure**
   - System must not imply failure
   - "Not done" is first-class, not secondary

3. **No Storage Orientation**
   - SelahOS is not for archiving, journaling, or accumulating data

4. **Phase Alignment**
   - Only expose what the user can currently carry
   - Remove features that require higher coherence

---

## Anti-Goals

SelahOS is NOT:

- a productivity system
- a habit tracker focused on streaks
- a journaling tool
- a self-improvement dashboard
- a place for analysis or introspection
- a system that pressures consistency

---

## Guiding Philosophy

- Ground before sky
- Contact before interpretation
- Reality before narrative
- Simplicity before completeness

---

## Evolution Rule

New features or layers are only introduced when:

> The current system is used consistently without resistance

Until then:
- simplify
- reduce
- lower friction

Never add to compensate for lack of usage.

---

## Final Definition

SelahOS is:

> A minimal, daily act of honest contact with reality,
> designed to stabilize the human system before expansion.
